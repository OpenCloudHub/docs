# CLAUDE.md - AI Assistant Guide for OpenCloudHub Documentation

This file provides comprehensive guidance for AI assistants working with the OpenCloudHub documentation repository.

## Repository Overview

**Project**: OpenCloudHub Documentation
**Purpose**: Documentation site for a master's thesis project on cloud-native MLOps platform engineering
**URL**: https://docs.opencloudhub.org
**Framework**: Jekyll 4.4.1 with Just the Docs theme (v0.10.1)
**Deployment**: GitHub Pages via GitHub Actions
**License**: MIT

### Project Context

OpenCloudHub is a research-driven MLOps platform demonstrating enterprise-grade machine learning lifecycle management on Kubernetes. This documentation repository serves as the primary knowledge base for the platform, covering architecture, workflows, and implementation details.

**Key Platform Technologies**:
- Kubernetes (container orchestration)
- ArgoCD (GitOps deployment)
- MLflow (experiment tracking and model registry)
- KServe (model serving)
- Prometheus/Grafana (monitoring)
- Keycloak (authentication)
- Gateway API & Istio (traffic management)
- CloudnativePG & MinIO (storage)
- Terraform/Terragrunt (infrastructure as code)

## Content Structure

### Page Front Matter

All markdown pages should include Jekyll front matter:

```yaml
---
title: Page Title
layout: default  # or 'home' for homepage
nav_order: 1     # Optional: controls navigation order
parent: Parent Page  # Optional: for hierarchical navigation
---
```

### Homepage (index.md)

- Uses `layout: home`
- Large title with `.fs-9` class
- Subtitle with `.fs-6 .fw-300` classes
- Structured with clear sections
- Includes note callout for project status

### Content Writing Guidelines

1. **Markdown Formatting**:
   - Use standard GitHub-flavored markdown
   - Headers: # for h1, ## for h2, etc.
   - Code blocks with language specification

2. **Just the Docs Classes**:
   - Font sizes: `.fs-1` through `.fs-9`
   - Font weights: `.fw-300`, `.fw-400`, `.fw-500`, `.fw-700`
   - Text colors: `.text-grey-dk-100`, etc.
   - Spacing: `.mb-0` through `.mb-8` (margin-bottom)

3. **Callouts**:
   ```markdown
   {: .note }
   This is a note callout.

   {: .warning }
   This is a warning callout.

   {: .important }
   This is an important callout.

   {: .highlight }
   This is a highlight callout.
   ```

4. **Navigation**:
   - Pages automatically appear in navigation
   - Use `nav_order` to control position
   - Use `parent` for hierarchical structure
   - Use `nav_exclude: true` to hide from navigation

1. **Build**:
   - Checkout code

   - Deploy to GitHub Pages environment

**Automated Updates**:
- Bundler dependencies (Ruby gems) - daily
- GitHub Actions - daily at 10:00
- Only direct dependencies for Bundler
- Max 10 open PRs for GitHub Actions

   ---

## Git Workflow and Branching

### Branch Naming Convention

For AI assistant sessions:
- Pattern: `claude/claude-md-<session-id>-<unique-id>`
- Example: `claude/claude-md-mi40cu6t9wkhrdco-01VMzT9P3esZK4ctNSc7ctEZ`
- **Critical**: Branch must start with `claude/` and end with matching session ID

### Commit Guidelines

1. **Commit Message Format**:
   - Use present tense ("Add feature" not "Added feature")
   - Be descriptive but concise
   - Reference issues when applicable

2. **Commit Scope**:
   - Keep commits focused on single logical changes
   - Don't mix content updates with configuration changes
   - Separate refactoring from feature additions

3. **Examples**:
   ```
   Add MLflow deployment documentation
   Update color scheme for better contrast
   Fix navigation ordering in platform guides
   Add callout styles to warning sections
   ```

### Pull Request Process

1. **Create PR** from feature branch to `main`
2. **CI must pass** (build succeeds)
3. **Review changes** in GitHub's diff view
4. **Merge** when approved
5. **Automatic deployment** triggers on merge to main

### Push Retry Logic

Due to potential network issues, implement retry logic for git operations:

**For `git push`**:
- Use: `git push -u origin <branch-name>`
- Retry up to 4 times on network failures
- Exponential backoff: 2s, 4s, 8s, 16s

**For `git fetch/pull`**:
- Prefer: `git fetch origin <branch-name>`
- Same retry logic: 4 attempts with exponential backoff

## Key Conventions

### File Naming

- **Markdown files**: lowercase with hyphens (e.g., `getting-started.md`)
- **Assets**: descriptive, lowercase with hyphens
- **Partials**: snake_case (e.g., `nav_footer_custom.html`)
- **Styles**: lowercase (e.g., `opencloudhub.scss`)

### Code Style

**YAML**:
- 2-space indentation
- Quotes for strings with special characters
- No quotes for simple strings

**Markdown**:
- 2-space indentation for nested lists
- Blank line before and after code blocks
- Blank line before and after headers

**SCSS**:
- 2-space indentation
- Meaningful variable names
- Group related variables together

### Documentation Standards

1. **Be Clear and Concise**:

2. **Structure Content**:
   - Use hierarchical headers
   - Break up long content with subheadings
   - Use lists for readability

3. **Code Examples**:
   - Always specify language for syntax highlighting
   - Include context and explanations
   - Test code examples before documenting

4. **Technical Accuracy**:

   - Link to official documentation

## Troubleshooting

### Common Issues

**Issue**: Changes not appearing in browser
**Solution**: Hard refresh (Ctrl+Shift+R) or clear browser cache

**Issue**: Jekyll build fails
**Solution**:
1. Check `bundle install` completed
2. Verify YAML front matter syntax
3. Check for broken links or missing images
4. Review build output for specific errors

**Issue**: Navigation not updating
**Solution**:
1. Verify `_config.yml` was restarted
2. Check `nav_order` values
3. Ensure parent-child relationships are correct

**Issue**: Styles not applying
**Solution**:
1. Check SCSS syntax
2. Verify color scheme name in `_config.yml`
3. Rebuild site (may need to clear cache)

### Build Errors

**Common Jekyll errors**:
- Invalid YAML front matter: Check indentation and syntax
- Liquid syntax errors: Review template tags
- Missing dependencies: Run `bundle install`
- Port already in use: Kill existing Jekyll process or use different port
